# Protocol v1

The authoritative wire schemas and route signatures are [OpenAPI](../../packages/protocol/openapi.json). `python scripts/generate_protocol.py --check` rejects DTO drift. Additive optional fields require extending the generator deliberately; no silent fallback to opaque maps. v2 uses a new route prefix; v1 remains served during a declared migration window.

## Pairing design

The bootstrap listener is HTTPS with the exact server SPKI pinned from the locally displayed QR. It has no transfer endpoints and cannot be upgraded to a plaintext fallback. QR tokens are 32 CSPRNG bytes, base64url without padding, 120-second lifetime measured with a monotonic clock, single-use, memory-only, hashed for comparison. The advertised UTC expiry is for display; wall-clock rollback cannot extend token validity. Issuing a new QR invalidates the old token. Token consumption and pending request creation are atomic.

Android creates a non-exportable Android Keystore signing key. Registration provides a self-signed client certificate and proof of possession: a signature over the UTF-8 string `phone-transfer/pairing/v1\n{deviceId}\n{displayName}\n{token}\n{SHA256(certificate DER)}`. Use canonical lowercase UUIDs, NFC display names without control characters, canonical base64 certificate/signature fields, and ECDSA P-256 / SHA-256 signatures encoded as ASN.1 DER sequences. The self-signed leaf must include non-CA basic constraints, digital-signature key usage and client-auth EKU. Validate lengths, UUID, signature, certificate algorithm, validity and client-auth usage before asking for PC approval. Display name is signed as well as identity and certificate so the approval prompt cannot be substituted independently. The PC shows the requesting device name and a comparison code derived from the public request. User confirmation is mandatory. Pending requests expire after 120 seconds. Status polling requires proof-bound request authorization; possession of requestId alone is insufficient. This authentication header is to be finalized in Phase 2 before exposing the endpoint.

The main HTTPS listener requires a registered client certificate. Leaf certificate fingerprints are allowlisted; the client pins server SPKI and checks validity and server-auth usage. Device identity is bound to the certificate record, never a caller-supplied header or IP. mDNS information is untrusted routing metadata.

## Upload and resume design

1. POST transfer metadata with total size (0–1 TiB), lowercase SHA-256, relative destination and per-device idempotency UUID. Metadata changes under the same key return `IDEMPOTENCY_CONFLICT`.
2. PATCH binary chunks, maximum 4 MiB, with exact `Upload-Offset`. The server streams to private staging; no whole-file buffering. Offset conflict returns `OFFSET_MISMATCH`; GET the transfer to reconcile, never guess progress.
3. Cancellation/disconnect before commit truncates the in-flight chunk. Only committed offsets are acknowledged. Retrying a response-lost append begins with GET status, avoiding duplicate bytes.
4. POST complete after all bytes. Zero-length uploads enter transferring then verifying without an empty chunk. Independently hash the staging file, compare constant-time, and move without overwrite on the same volume. Destination conflict is a typed recoverable error; no overwrite default.
5. DELETE serializes with verification and rename; terminal states cannot be rewritten. Ownership is per device for all transfer routes, including status and cancel.

## Download design

Return a strong SHA-256 ETag and stream a stable open handle. Resume requires `Range: bytes=n-` and `If-Match`; reject changed files with 412. Support one range only; use 416 for invalid ranges. The final Android file is marked complete only after digest comparison. SAF providers may not seek: use app-private staging and an explicit SAF export step; check available space, preserve staging after failed export, never claim a partial destination is complete.

## Paths and limits

HTTP framework decodes query paths exactly once; domain rejects residual percent characters, backslashes, absolute paths, ADS colons, dot segments, empty components, control characters, trailing dots/spaces, reserved Windows names and non-NFC input. Windows storage must additionally reject reparse points and validate final handle containment while retaining non-delete-shared directory handles. String validation is not a filesystem escape guarantee.

Set listing/history pagination cap 200, JSON body limit 128 KiB, text maximum 65,536 characters, chunk limit 4 MiB, bounded per-device concurrency and total staging quota. Limits must be enforced before or while reading, including chunked HTTP bodies. Stable error codes, retryability and requestId are safe for UI; exceptions, physical paths and secret text are not response details.

## Text/history design

`plainText` and `url` are separate kinds. Only explicit user action can open an http/https URL; never shell-execute supplied content. History can be disabled, bounded or cleared. Retrying sends uses per-device idempotency keys. A future authenticated cursor/long-poll route provides PC-to-Android delivery without an Android listener.
